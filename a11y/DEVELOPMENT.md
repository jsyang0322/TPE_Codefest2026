# 無障礙輔助（a11y）開發說明

這份文件說明 `a11y/` 做了什麼、怎麼做的、用了哪些工具、程式跑在哪裡，以及還沒驗證的地方。
程式碼在 `TPE_Codefest2026` 的 `feat/a11y` 分支；TownPass 的修改放在 `a11y/townpass/a11y-share.patch`。

## 一句話總結

給長輩、視障者用的台北通輔助服務，兩個功能：

- **A. 常見問題語音查詢**：用說的問台北通的常見問題，手機念出官方答案。
- **B. 讓家人幫忙**：長輩同意後，家人看得到長輩整個台北通的畫面，並遠端幫忙點按、打字。

執行時**不使用任何 AI**：搜尋是關鍵字比對，提示語音是固定模板。開發時用 Claude Code 協助寫程式（見最後一節）。

## 程式跑在哪裡

| 部分 | 跑在哪裡 | 說明 |
| --- | --- | --- |
| 網頁（長輩頁、家人頁、常見問題頁） | 後端程式一起提供 | 純 HTML、CSS、JavaScript，不用建置 |
| 後端（API、綁定、轉送畫面） | **比賽期間：組員的 Mac**；之後：資訊局的伺服器 | Python 的 FastAPI。用 `cloudflared` 通道給 Mac 一個公開的 https 網址 |
| 語音辨識、朗讀 | 長輩的手機 | 透過台北通 App 內建的功能，不用雲端語音服務 |
| 拍畫面、執行家人的操作 | 長輩手機上的台北通 App | 套用 `townpass/a11y-share.patch` 才有 |
| 常見問題的資料 | 後端的 SQLite 資料庫 | 每 24 小時從台北通官方網站同步一次 |

開發過程中曾經規劃用 Google Cloud Run 放後端，後來依你的要求改成跑在自己的電腦。**現在不使用任何雲端主機。**
`cloudflared` 只負責把外面的連線轉到 Mac；入門指引第 07 章允許比賽期間用這種通道對外提供本機服務。

## 架構

```
長輩的 iPhone：台北通 App                  組員的 Mac（後端）                 家人的手機：瀏覽器
 ├ 無障礙輔助網頁 ── 登入、綁定、常見問題 ──→ FastAPI ←──── 登入、輸入數字碼 ──── 家人頁
 └ 分享功能（Flutter）── 畫面圖片 /ws/share ──→ 轉送 ────── 畫面 /ws ────────→ 顯示畫面
       在同一位置點按 ←──────── 指令 ────────── 轉送 ←── 點畫面 POST /commands ──┘
                                   │
                        cloudflared 通道（公開 https 網址）
```

## 功能 A：常見問題語音查詢

**流程**：
1. 打開頁面，一次下載全部常見問題（51 題，只取中文）。
2. 按下半部的說話按鈕，台北通 App 用手機的語音辨識聽寫。
3. 網頁在手機上比對關鍵字和同義詞，找出最像的問題。
4. 用手機朗讀官方答案。

**做法**：
- **資料來源**：[台北通官方網站｜功能教學與Q&A](https://id.taipei/tpcd/about/faq)，透過網站本身使用的公開 API 同步，答案保留原文。後端啟動時同步一次，之後每 24 小時一次（`backend/faq_sync.py`）。
- **搜尋**：搜尋在手機上做，所以下載完之後切成飛航模式也查得到（`frontend/js/faq-search.js`）。關鍵字和同義詞在 `backend/data/faq_keywords.json`、`faq_synonyms.json`，由 Claude Code 起草、團隊確認。
- **找不到答案時**：可以換個說法再問、看全部問題，或撥 1999。
- **用到的 App 功能**：都是 TownPass 原本就有的 `voice_listen`、`tts_speak`、`phone_call`，**這個功能不用改 App**。
- **在電腦上測試**：沒有 App 時，改成用打字代替說話，用瀏覽器內建的語音朗讀。

## 功能 B：讓家人幫忙

### 1. 綁定與授權

1. **產生數字碼**：長輩按「讓家人幫我」，手機產生 6 位數字碼並念出來。
2. **家人輸入**：家人在自己的手機輸入這組數字。
3. **長輩同意**：長輩的手機問「王小美 想看你的畫面、幫你操作，同意嗎？」，長輩用說的或按按鈕回答。
   - 「同意」「不同意」用固定規則判斷（`backend/consent.py`），沒有用 AI。

數字碼的規則：5 分鐘換一組、只能用一次；同一人輸錯 5 次要等 1 分鐘。原本還有 QR code，依你的要求拿掉了。

授權只在長輩「這一次登入」有效。這些情況都會立刻結束：
- 長輩停止分享
- 長輩登出
- 長輩閒置 30 分鐘

帳號是兩個模擬帳號（王阿伯、王小美），登入與授權狀態只存在後端記憶體，後端重開就要重新登入、重新綁定。

### 2. 分享整個台北通的畫面

1. **交給 App**：長輩同意後，網頁把這次分享的通行碼交給台北通 App。用的是新加的 `a11y_share_start`，App 只接受無障礙輔助網頁送來的訊息。
2. **拍畫面**：App 每秒檢查一次，畫面有變化才把**整個 App 的畫面**拍成圖片送到後端，後端轉給家人。
   - 網頁服務不是 Flutter 畫的，拍出來那一塊是空白，所以另外拍網頁的截圖，疊在正確位置。
   - App 在背景時暫停拍。
3. **家人操作**：家人點畫面上的位置，App 在長輩手機的同一個位置按一下，畫一個圈，並念出「王小美 按了『下一步』」。
   - 網頁裡的按鈕用 JavaScript 按。
   - 框框就是長輩的手機，所有操作都在框框裡：點欄位時框框下方出現打字框；拖曳或滾輪捲動；框框下方的按鈕列有「上一頁」「首頁」「打字」。
   - 長輩按「同意」後，App 自動關掉無障礙輔助回到台北通首頁。
   - 長輩的手機只負責被同步畫面和「停止分享」；操作都由家人做。

### 3. 保護長輩的設計

| 保護 | 做法 |
| --- | --- |
| 重要按鈕要長輩同意 | 按鈕上有「送出、付款、確認、申請、刪除…」等字時，先在長輩手機上問，同意才按。問的畫面不在拍下的畫面裡，問的時候家人的操作都不執行，所以家人按不到「同意」 |
| 密碼不給家人填 | 密碼欄位家人不能填，畫面上本來就只顯示圓點 |
| 隨時能停 | 長輩畫面下方一直有「正在看你的畫面」和「停止分享」 |
| 只有無障礙輔助網頁能開始分享 | App 檢查送來訊息的網址，其他網頁不能要求 App 開始分享 |

### 4. 電腦上的測試方式

電腦瀏覽器沒有台北通 App，所以另外做了一個**模擬服務頁**（`frontend/demo/service.html`，假的申辦表單）。這一頁自己載入開源的 rrweb，把網頁的變化傳給家人。在電腦上開兩個視窗，就能模擬兩支手機。

## 還沒驗證、要注意的地方

- **還沒在真的 iPhone 上跑過**：要組員照 `IPHONE_TESTING.md` 測。
- **cloudflared 通道還沒實測**：測試就得把電腦公開到網路上，我沒有這樣做。
- **通道網址會換**：cloudflared 每次重開網址都會換，換了就要重新 `flutter run`。
- **畫面會慢一點**：家人看到的畫面會慢大約 1 秒，動畫會一格一格的。
- **系統畫面看不到**：鍵盤、權限詢問這類系統跳出來的畫面，家人看不到。
- **只有圖示的按鈕不會先問**：按鈕上只有圖示、沒有字時，App 不知道它是不是重要按鈕，會直接按。
- **停車費最後的「是」不會再問**：「前往繳費」會先問長輩；之後提醒框的按鈕只寫「是」，App 看不出是付款，會直接按。
- **繳交規定**：入門指引第 08 章要求繳交「修改後的 TownPass」。修改檔要套用到你們的 TownPass 並推上去，這件事要團隊決定。

## 開發過程中改過的決定

| 一開始 | 後來 | 原因 |
| --- | --- | --- |
| 家人只能幫忙繳停車費 | 分享整個服務網頁 | 你要直接分享頁面 |
| 分享服務網頁 | 分享整個台北通 App 的畫面 | 你要在 App 中授權後看到全部畫面 |
| 數字碼＋QR code | 只用 6 位數字碼 | 你覺得數字碼就夠了 |
| 後端放 Cloud Run | 後端跑在自己的電腦，用通道對外 | 你不要用雲 |
| 家人只能用按鈕捲動 | 家人可以直接拖曳、用滾輪捲動，並能回到首頁 | 實測時發現不方便 |
| 操作按鈕在框框外；同意後停在無障礙輔助頁，從「打開要辦的服務」開服務 | 框框＝長輩的手機，按鈕列和打字框都在框框裡，拿掉「往上」「往下」；同意後直接回到台北通首頁，App 裡不再顯示服務清單 | 3 號實測：框框外的按鈕不直覺，無障礙輔助頁裡也沒什麼可以讓家人操作 |
| Demo 要自己找有「送出」按鈕的真服務頁 | 先做了示範服務「交通罰單」（假資料），後來拿掉，改用台北通原本的「帳務 › 停車費」 | 你問為什麼不用 App 原本的繳費功能；實際走一次，原本的停車費頁就能從查詢走到繳費完成 |
| 介面是單純的按鈕和文字 | 改成台北通的樣子：青綠色標題列（在 App 裡用 App 的）、白底、圓角卡片與按鈕、數字碼一格一格；家人看畫面時整個螢幕是長輩的畫面，頁面不捲動 | 你覺得介面很醜、要參考台北通；長輩和家人都用 iPhone |

## AI 使用聲明

- 開發階段用 Claude Code 協助撰寫程式、測試、文件，並起草搜尋用的關鍵字與同義詞，經團隊確認。
- 執行時不使用任何 AI 或 LLM。
